# TempoFast — Project Rules

## Application Type

This is an **API-only** Laravel server. There is NO frontend, NO Blade views, NO Inertia.js.

- All responses are JSON (`application/json`)
- All routes are defined in `routes/api.php`
- Do NOT create Blade views, Inertia pages, or frontend assets
- Do NOT use `tailwindcss-development` skill — there is no frontend
- Use Eloquent API Resources for all API responses
- Use Form Requests for all input validation
- Use API versioning (e.g. `/api/v1/...`)

## Database Schema — Omnify (CRITICAL)

**ALL database structure changes MUST go through Omnify schemas.**

- Schema files live in `database/schemas/` as YAML
- NEVER create Laravel migrations manually for **schema changes** (`php artisan make:migration` is FORBIDDEN for table structure)
- Exception: `php artisan make:migration` is OK for **seed data migrations** ONLY when the data is critical and MUST NOT be missed during production deploy (e.g. default roles, system config). Prefer Laravel Seeders (`database/seeders/`) for all other seed data
- To add/modify tables: edit or create YAML in `database/schemas/`, then run `npx omnify generate`
- Omnify generates migrations to `database/migrations/omnify/`
- Use `npx omnify add` to scaffold new schemas
- Use `npx omnify validate` to verify schemas before generating
- Use `npx omnify list` to see existing schemas
- Models are auto-generated by Omnify codegen to `app/Models/`
- TypeScript types are generated to `resources/js/types/models/` (for API client consumers)

### Workflow

1. Define schema in `database/schemas/*.yaml`
2. `npx omnify validate` — verify
3. `npx omnify generate` — generate migrations + models
4. `php artisan migrate` — apply to database

## Naming Conventions

### Routes & URLs

- Use **kebab-case** for URL segments: `/api/v1/user-profiles`, `/api/v1/order-items`
- Use **plural** nouns for resource endpoints: `/products`, `/categories`
- Nested resources max 2 levels: `/organizations/{organization}/branches`
- Route names use **dot notation**: `api.v1.products.index`, `api.v1.products.store`

### PHP

- Controllers: `{Model}Controller` (singular) — `ProductController`, `OrderItemController`
- Form Requests: `{Action}{Model}Request` — `StoreProductRequest`, `UpdateProductRequest`
- API Resources: `{Model}Resource` / `{Model}Collection` — `ProductResource`, `ProductCollection`
- Policies: `{Model}Policy` — `ProductPolicy`
- Services: `{Model}Service` — `ProductService`
- Actions: `{Verb}{Model}` — `CreateProduct`, `ApproveOrder`
- Enums: `{Model}{Property}` in TitleCase — `OrderStatus`, `UserRole`

### Files & Directories

- Controllers: `app/Http/Controllers/Api/V1/`
- Form Requests: `app/Http/Requests/Api/V1/`
- API Resources: `app/Http/Resources/Api/V1/`
- Services: `app/Services/`
- Actions: `app/Actions/`
- Policies: `app/Policies/`
- Enums: `app/Enums/`

## API Response Format

### Success Response

```json
{
  "data": { ... }
}
```

For collections with pagination:

```json
{
  "data": [ ... ],
  "meta": {
    "current_page": 1,
    "last_page": 5,
    "per_page": 20,
    "total": 100
  },
  "links": {
    "first": "...",
    "last": "...",
    "prev": null,
    "next": "..."
  }
}
```

### Error Response

```json
{
  "message": "Human-readable error message",
  "errors": {
    "field_name": ["Validation error 1", "Validation error 2"]
  }
}
```

### HTTP Status Codes

| Code | Usage |
|------|-------|
| 200  | Success (GET, PUT/PATCH) |
| 201  | Created (POST) |
| 204  | No Content (DELETE) |
| 400  | Bad Request |
| 401  | Unauthenticated |
| 403  | Forbidden |
| 404  | Not Found |
| 422  | Validation Error |
| 429  | Too Many Requests |
| 500  | Server Error |

## Query & Performance

- Always use `select()` to limit columns when not all fields are needed
- Use `whenLoaded()` in API Resources for optional relationships
- Paginate all list endpoints (default 20 per page, max 100)
- Use query scopes for reusable filters
- Index frequently queried columns in Omnify schemas

## Testing (Pest ONLY)

- **Must use Pest** — never PHPUnit style. Use `it()` / `test()` + `expect()` syntax
- Use factories for all test data — never insert raw DB rows
- Test file naming: `tests/Feature/Api/V1/{Model}Test.php`

### 正常系 (Normal / Happy Path) — REQUIRED

Every endpoint must test successful scenarios:

- Correct HTTP status code (200, 201, 204)
- Response JSON structure matches API Resource
- Data is persisted/updated/deleted correctly (`assertDatabaseHas`, `assertDatabaseMissing`)
- Pagination works for list endpoints
- Relationships are loaded correctly

### 異常系 (Abnormal / Error Path) — REQUIRED

Every endpoint must test failure scenarios:

- **Validation errors (422)**: missing required fields, invalid formats, boundary values
- **Not found (404)**: non-existent resource IDs
- **Unauthorized (401)**: unauthenticated access
- **Forbidden (403)**: authenticated but insufficient permissions
- **Conflict/Business logic errors**: duplicate entries, invalid state transitions
- Assert error response format (`message`, `errors`)

### Test Structure

```php
// tests/Feature/Api/V1/ProductTest.php

describe('GET /api/v1/products', function () {
    // 正常系
    it('returns paginated products', function () { ... });
    it('filters products by category', function () { ... });

    // 異常系
    it('returns 401 when unauthenticated', function () { ... });
});

describe('POST /api/v1/products', function () {
    // 正常系
    it('creates a product with valid data', function () { ... });

    // 異常系
    it('returns 422 when name is missing', function () { ... });
    it('returns 422 when price is negative', function () { ... });
    it('returns 403 when user lacks permission', function () { ... });
});
```

## What NOT to Do

- Do NOT create manual migrations — use Omnify schemas
- Do NOT create frontend files (Blade, React, Vue, etc.)
- Do NOT return HTML responses
- Do NOT install frontend packages (except dev tooling like TypeScript types)
- Do NOT use `DB::raw()` unless absolutely necessary — prefer Eloquent
- Do NOT return models directly from controllers — always use API Resources
